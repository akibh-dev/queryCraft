# Simulation, data and save contracts

Read this before implementing a level, Run, Compare, Submit, saves, or score display. Use one Vite app. Put Zod schemas and their inferred TS types in `src/domain/`. Put pure simulation and fixture evaluation in `src/engine/`. Keep React, browser storage, clocks, randomness and network access outside the engine. The numbers below are proposed gameplay constants for model `mvp-1`. Publish them with the in-game model notes.

## Contract to freeze first

Implement each public name once. Import these types throughout the app. The following shorthand specifies the contents of each type. A field ending in `?` is optional. Level authors ship JSON, not executable functions.

| Name             | Required data                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Column           | `name`, `type` (bigint, text, timestamp or boolean), `nullable` (boolean, default false), `averageBytes`, `distribution: {kind: 'unique' or 'uniform', distinctCount}`. Numeric ranges also declare `min` and `maxExclusive` on the distribution. Use safe integers for bigint fixture values.                                                                                                                                                                                               |
| IndexModel       | `id, column`. All indexes are single-column B-trees in this release.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| TableModel       | `name, rowCount, avgRowBytes, columns: Column[], fixedIndexes: IndexModel[]`. Fixed indexes participate in planning and already exist in every attempt.                                                                                                                                                                                                                                                                                                                                      |
| Workload         | `readsPerSecond, insertsPerSecond, updatesPerSecond`. A cold-cache assumption applies throughout v0.1.                                                                                                                                                                                                                                                                                                                                                                                       |
| QuerySpec        | `table, select: string[], predicates: Predicate[]`. Equality has `{op:'eq',column,value}`. Numeric range has `{op:'range',column,gte?,lt?}`. Provide `validateLevel(raw)`, `simulate(level, attempt)`, `checkCorrectness(level, fixture)` and `evaluateObjectives(level, baseline, result, correct)`. Call the last function with the boolean from checkCorrectness. A level's baseline always comes from `simulate(level, {selectedIndexIds: level.initialIndexIds})`. Reuse it throughout the attempt. A fixture verdict can be cached per level version because index selection preserves the fixed query. On Submit, evaluate the current verified run; a changed selection requires another Run. Keep formatting, persistence and star animations outside this API.

## Validation boundary

Validate content when assembling the game and validate all storage/import payloads before using them. Enforce identifiers unique in their scope, existing table/column/index/fixture references, matching query and fixture types, valid projection columns, fixture nullability and expected projection arity, and fixed and optional index IDs and indexed columns disjoint. Permit at most one index per column. Permit only the listed fields and operators. Require at least one projected column, one mandatory objective, three progressive hints, and one reference solution for each level. Require nonempty stretch tiers for a three-star level.

For this model use 0–1 billion virtual rows, 1–8192 bytes per row and per column, at most 16 columns and 16 index options, finite workload rates in [0, 1 million] per second, and finite nonnegative objective values. For nonempty tables use distinct counts from 1 through rowCount; unique means distinctCount equals rowCount. Empty tables use distinctCount zero. A range requires numeric column bounds with min < maxExclusive and at least one finite query bound. A query with both bounds requires gte < lt. Reject duplicate predicate columns so the independence assumption never multiplies two filters on the same column. Reject unsupported SQL constructs at content validation. Stats describe non-null keys for estimation. A null equality predicate has zero selectivity. Hand-authored equality levels use a key declared present in the modeled population. If writes and reads both equal zero the workload share below is zero.

## Implement the cost model in this order

1. Derive per-predicate selectivity. A present equality key has fraction 1/distinctCount. A numeric range has fraction equal to the length of the overlap of [gte, lt) and [min, maxExclusive), divided by the domain length. Substitute domain endpoints for omitted bounds. Clamp to [0,1]. On a nonempty table combine independent predicate fractions with multiplication; an empty predicate list matches all rows. Round row estimates to nearest integer. Return zero matches for empty tables.
2. Enumerate the full scan, then one candidate for each active fixed or optional index whose column has a predicate. The index candidate visits rows matching its own predicate; any further filters run after row fetch. Record final matchingRows after all filters for every plan. No index intersection, sorting, pagination or arbitrary SQL in these campaign levels.
3. Use an 8192-byte page. Data page count P = ceil(N × avgRowBytes / 8192). For each index estimate entryBytes = column.averageBytes + 8, fanout = max(2, floor(8192 / entryBytes)). For N > 0, tree height H is the smallest integer h >= 1 where fanout^h >= N; otherwise H = 0. Use integer iteration for exact powers. Optional index size = ceil(N × entryBytes / 8192) × 8192 bytes. This simplified size covers entries with page rounding. Exclude fixed index storage and maintenance from the reported _additional_ cost.
4. For a scan, rowsExamined = N, sequentialPagesRead = P and randomPagesRead = 0. For an index let V be the rounded number of rows matching its predicate. Estimate distinct data pages fetched using uniform random placement: zero if P = 0 or V = 0, one if P = 1 and V > 0, otherwise ceil(−P × expm1(V × log1p(−1/P))). Clamp the result to [0, min(P,V)]. Index plan rowsExamined = V, randomPagesRead = H + fetched data pages, sequentialPagesRead = 0. This approximation treats traversal and tuple fetch separately and omits extra range leaf reads. Output that assumption in the model notes.
5. estimatedCostUnits = sequentialPagesRead + 4 × randomPagesRead + 0.001 × rowsExamined × max(1, predicate count). estimatedLatencyMs = 0.1 + 0.02 × estimatedCostUnits. Choose minimum unrounded cost; an exact tie prefers scan, then lexicographically smallest index ID (code-unit order). Return alternatives in canonical order (scan first, then by index ID). Expose losing candidates for Compare. Label latency as estimated, never p95.
6. writeShare = (insertsPerSecond + updatesPerSecond) / total operations per second. writeOverheadPct = 15 × sum(optional active tree heights) × writeShare. This is a synthetic workload-weighted maintenance penalty, expressed as a percentage of baseline workload cost under the model's equal baseline operation weights. Describe higher write share and extra maintained indexes in the trace. Keep this penalty separate from query latency; a useless index can increase storage and writes while leaving the read plan unchanged.
7. latencyReductionPct = 100 × (baseline.estimatedLatencyMs − result.estimatedLatencyMs) / baseline.estimatedLatencyMs. Latency has a positive floor. Compare unrounded values against the objectives. Score zero stars if correctness or any mandatory check fails. Award one for a pass, two if all silver checks also pass, three if all silver and all gold checks pass. Playing hints, resetting the current draft and repeated attempts do not change this evaluation.

## Worked check for the first puzzle

For `w1-l1-needle-in-a-million` set N = 1,000,000, avgRowBytes = 128, email unique, email.averageBytes = 32, reads = 95, inserts = 5, updates = 0. Start with a fixed id index, zero optional indexes, and one email equality predicate. The full scan reads 15,625 pages and examines 1,000,000 rows. Its cost is 16,625 units or 332.6 estimated ms.

Select the optional email index. Each entry is 40 bytes, fanout is 204, height is 3. The lookup reads three index pages plus one data page, examines one row, and costs 16.001 units or 0.42002 estimated ms. The optional index occupies 4,883 pages or 40,001,536 bytes. The workload-weighted write penalty is 15 × 3 × 0.05 = 2.25%. A mandatory 70% latency reduction and 42,000,000-byte ceiling both pass. An index on name alone still produces the original scan and fails the reduction requirement. Verify the example by running the engine before shipping a level. Use displayed values from the result everywhere; the UI should contain no fixture-specific timing constants.

## Correctness and test checklist

Evaluate the structured query on its tiny fixture independent of cost estimation. SQL WHERE keeps rows where all predicates are true; null operands yield unknown for equality and range and the row is excluded. Preserve projection column order, distinguish types and preserve duplicates. Compare result rows as a multiset of typed arrays (canonical serialized tuples plus occurrence counts). Launch levels require no ordering. A fixture mismatch produces zero stars even with a fast plan.

| Test input                                                                                      | Required outcome                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First puzzle above                                                                              | Assert baseline, winning plan, bytes, page counts, maintenance penalty, and stars from the actual objectives. Approximate equality only for floating-point snapshots. |
| Small table or broad filter                                                                     | Scan can win with a relevant index active. Verify explanation and additional storage.                                                                                 |
| Boundary range and two predicates                                                               | Lower endpoint included; upper endpoint excluded. Index rowsExamined uses its own predicate. Other predicates affect final matchingRows.                              |
| Empty table, one-page table, one billion virtual rows                                           | Finite deterministic values; execution allocates only in proportion to schema, options and fixture size.                                                              |
| Two equally cheap indexes; same input with options reordered                                    | Same selected plan, metrics and canonical ordering of alternatives. Exercise empty table to confirm scan wins an exact tie.                                           |
| Duplicate result rows, null operands, empty result and a deliberately incorrect expected result | Multiset comparison and mandatory correctness gate hold.                                                                                                              |
| Invalid schema, malformed imports, unknown IDs or mixed level/model versions                    | Return typed validation errors and keep the last valid game state. Do not compare stale results against a different baseline.                                         |
| Repeated runs, edits after a passing run, multiple read/write mixes                             | Stable run and score; edited draft cannot submit old result. More writes increase workload penalty at equal selection.                                                |

## Save boundary

The persistence owner implements a browser adapter with `loadProgress()`, `saveCompletion(record)`, `saveSettings(settings)`, `exportProgress()`, `importProgress(json)`, and `resetProgress()`. The engine supplies the result and stars only. Use the localStorage key `querycraft.progress.v1`. Store one JSON object with `schemaVersion:1`, `completions` (array), and `settings:{theme:'system'|'light'|'dark', reduceMotion:boolean}`. A completion contains `{levelId,levelVersion,modelVersion,stars,selectedIndexIds}`. Stars range from 1 through 3. Sort option IDs, and keep the highest star result per exact (levelId, levelVersion, modelVersion); keep the existing result on a tie. Lower-scoring replays preserve the best. Old known level completions can unlock progression; label historical stars separately, and rank only identical versions.

Reject imports larger than 256 KiB before reading their contents. Bound the completion array to 256 records and check ID lengths, star range, unique option IDs and supported schema before merging. Accept an older model version as historical for known levels; validate active-version choices against the current catalog. Validate exports on import before touching current data. Merge by the same best-result rule, preserve current device settings unless the UI explicitly offers to restore imported settings, and only replace the saved value after successful validation and serialization. Read the latest stored value immediately before merging a completion. Coordinate simultaneous writers with a same-origin Web Lock when available; refresh state on the storage event. Pending state and last valid progress should survive a failed write in the current tab. Handle unavailable, full, invalid, or future-version storage explicitly. Keep gameplay usable in memory and surface save status. For invalid or unsupported stored documents preserve the original until the player chooses recovery. Reset current level restores initialIndexIds and clears the draft run; global reset acts only on this app's progress key after explicit confirmation.
